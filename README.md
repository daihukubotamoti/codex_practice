# BECOMING.

**昨日の自分を、今日の自分が超えていく。**

「こもれび鍛錬記」の既存プロジェクトを改修した、トレーニングと日々の変化を残すパーソナル成長アーカイブ。React + TypeScript + Vite / IndexedDB / PWA。ログイン、外部API、サーバー側DBは不要です。

## 起動・検証

Node.js 22.12以上（Node 24で検証）で、このフォルダから実行します。

```sh
npm ci
npm run dev
```

```sh
npm test           # 移行・旧XP・章の境界・バックアップ・集計など14テスト
npm run build     # TypeScriptチェック＋本番PWAビルド
npm run preview   # 本番ビルドのローカル確認（既定ポート4173）
npm run test:e2e   # 実ブラウザ＋実IndexedDBでの機能・移行・オフライン検証
```

E2Eは `/usr/bin/chromium` を使います。別のPCでは `playwright.config.ts` の `executablePath` を削除し `npx playwright install chromium` を実行するか、インストール済みのChrome/Chromiumに合わせてください。iPad Safari実機での最終検証は別途必要です。

## 画面と機能

- **Overview** — 雑誌の見開きに着想したモノクロのホーム。今日の日付、現在の章・レベル・次章への進捗、累計トレーニング日数、今月の日数・種目記録件数、自己ベスト、週の履歴、記録開始、休息日の登録。
- **Training** — 自由入力の種目、セットごとに異なる重量・回数、セット追加・削除、前回セットの引き継ぎ、任意の種目別所要時間、過去記録の編集。入力中も下書きをIndexedDBへ保存し、再起動後に復帰できます。
- **Journal** — 今日頑張ったこと、気分、自分への一言、写真1枚。トレーニングのない日にも保存可能。同日の日記は更新されます。下書きも保存。写真は最大1440pxのJPEGへ端末内で圧縮（通常約450KB以下、最大約1.1MB）。JPEG/PNG/WebPを受け付け、HEICは事前変換が必要です。写真の表示はモノクロ、保存されるJPEGは元の色を保持します。
- **Archive** — 月間カレンダーの `●` トレーニング、`○` 日記、`—` 休息、`↗` 自己ベスト。日付からトレーニングと日記を確認・編集・削除できます。休息日は取り消し可能。
- **Growth** — XP・章・レベル、1か月／3か月前との比較、種目別重量グラフ・PB更新、目標、節目、週間ミッション、未来への手紙。
- **Review** — 月・年を選んで随時生成するレビュー。トレーニング日数・セット数・時間・自己ベスト・日記・休息・最長連続日数・前期間との比較。月途中の記録も振り返れます。1200×1600のPNG画像に書き出し、保存・共有できます。
- **設定** — 表示名、種目の変更・削除、JSON書き出し・復元、移行前／復元前の控えの書き出し。

### 数値の定義

- **トレーニング日数／回数**は、1日に複数種目を記録しても1日と数えます。「種目記録」は保存した記録の件数です。独立したセッションの開始・終了は計測していません。
- **時間**は入力された種目の所要時間だけを合計。時間未入力の旧記録に推定時間は足しません。全件未入力なら `—` を表示します。
- **自己ベスト**は旧仕様を維持し、同じ種目の1セットの `重量×回数` の最大値。過去に保存した記録より大きい場合に更新とします。最初の重量ありの記録も対象。自重（0kg）はPB対象外ですが通常XPを獲得します。
- 比較・グラフの**最大重量**はその日／期間までの実測の最大kg値です。PBの重量×回数スコアとは区別します。比較対象の過去データと、それ以降のデータが揃わなければ「まだ、比べなくていい」と表示。
- **最長連続日数**は連続したトレーニング日付の最大数です。休息によって経験値やランクが減ることはありません。

### ランク・XPの互換性

旧アプリと同じく **1セット10XP、自己ベスト更新で20XP、100XPごとにレベルアップ**。日記・写真・手紙・目標・ミッションには追加XPを付与しません。記録から再計算する方式も維持しており、記録の編集・削除でXPが変わる場合があります。時の経過や休息で減ることはありません。

| 章  | ランク      | レベル | 必要累計XP |
| --- | ----------- | ------ | ---------- |
| 01  | BEGINNING   | 1〜3   | 0          |
| 02  | IN MOTION   | 4〜7   | 300        |
| 03  | CONSISTENCY | 8〜14  | 700        |
| 04  | EVOLUTION   | 15〜24 | 1400       |
| 05  | BECOMING    | 25〜   | 2400       |

旧ランクのレベル4・8・15の境界と進捗は維持し、最後に新しい章を追加しました。章をまたぐトレーニング保存時には、文字を中心とした短い演出を表示します。動きを減らすOS設定ではアニメーションを無効化します。

### 目標・手紙

目標は自由な目標（手動で達成）、週1〜7日のトレーニング（毎週月曜更新）、種目の最大重量の3種類。登録・編集・削除できます。

手紙は指定日以降に画面で読めます。ただし、保存データ／JSONでは平文です。暗号化・厳密な時間ロック・プッシュ通知ではありません。端末の日付を変更すると表示可否も変わります。

## 既存データを保持する仕組み

**アプリ名が変わっても、保存先は変更していません。**

- IndexedDB名 `komorebi-training` / DBバージョン `1` / store `journal` / キー `state` を引き継ぎます。
- 状態スキーマだけ `version: 1` → `version: 2` に変更します。`load()`は既存データを検証してから、トランザクション内で元の生データを `legacy-v1-backup` に保持し、新しい項目を空配列として追加します。旧記録・種目・休息日・表示名は保持、キャラクター用設定は新UIに持ち込みません。
- 不正または未対応の状態ではエラーを出して停止し、初期化や元データの上書きをしません。
- 保存はrevisionをトランザクション内で確認し、別タブの新しい記録を古い状態で上書きしません。競合時は下書きを控えて再読み込みしてください。同時編集は避け、普段は一つのタブで使ってください。
- 下書きは `draft-training` / `draft-journal` に保存し、正式保存完了後に削除します。
- 旧版・新版のJSONを復元できます。内容の検証と置換確認を行い、復元直前の状態も `draft-pre-restore-backup` に保持します。バックアップは50MB以下。写真等により大きくなるため定期的に書き出してください。
- 控えは設定画面からダウンロードできます。あくまで同じ端末内なので、サイトデータ削除に対する保険にはなりません。外部にJSONを保存してください。

**同じ端末・同じブラウザ・同じURLで更新してください。** URLを変えたり、Safariとホーム画面アプリを切り替えると保存領域が異なる場合があります。移行前にバックアップしてください。SafariのWebサイトデータの削除・容量不足・OSのストレージ整理で記録が消える可能性があります。プライベートブラウズは永続保存に向きません。

端末を操作できる人は記録を閲覧できます。ログイン認証、クラウド同期、サーバーへのバックアップはありません。JSONには日記・写真・手紙を含むため、GitHubにコミットしたり公開したりしないでください。

## iPadとPWAの利用

GitHub Pagesの既存URLを引き継ぎます。

`https://daihukubotamoti.github.io/codex_practice/`

公開処理が完了した後、iPadのSafariで開き、共有 → **ホーム画面に追加**。初回のオンライン読み込み完了後はオフラインでも利用できます。新しいバージョンが検出されたら更新案内を表示します。更新前に下書きを保存し、Service Workerを切り替えます。初回リニューアル時に旧画面が残る場合は、Safariの該当タブとホーム画面アプリをいったん閉じ、オンラインで開き直してください。以後は更新案内の「更新する」を選べます。アプリを更新するためにSafariのサイトデータを削除しないでください。

PWAアイコン・アプリ名も変更しています。iPadに既に追加したアイコンの名前や画像はOSが旧表示を保持する場合があります。再追加の前にJSONを書き出し、移行先で記録を確認してください。

`.github/workflows/deploy.yml` はmainへのプッシュでテストとビルドを実行して `dist/` をGitHub Pagesへ公開します。GitHub側はSettings → Pages → SourceをGitHub Actionsに設定済みであることが前提。ドメインのルートまたはサブパスへ相対パスで配置できます。

開発サーバーはアプリ開発用です。LANのHTTPではPWAを使えません。iPadでのオフライン検証にはHTTPSの公開先を使ってください。クラウド環境のPublishはWebアプリの公開とは別です。

## 実装の構成

- `src/App.tsx` — ナビゲーション、保存、下書き、更新案内、章の演出
- `src/components/` — ホーム／トレーニング／日記／アーカイブ／成長／レビュー／設定
- `src/model.ts` — データ型、旧版からの移行、バックアップ検証、XP、集計、目標、節目
- `src/db.ts` — 既存DBの継続利用、安全な移行・保存、競合検出、下書き
- `src/media.ts` — 端末内の写真圧縮、JSONダウンロード、レビュー画像生成
- `src/style.css` — モノクロのデザインシステム、縦横iPad・スマホのレスポンシブ、動きを減らす設定
- `vite.config.ts`, `public/`, `index.html` — PWA、アイコン、メタ情報
- `tests/` — 単体・実ブラウザ検証（テスト用の画像は人工的に生成したもの）

ランタイム依存の追加はありません。旧キャラクターのコンポーネント・セリフ・アニメーションは削除。建築的な抽象ビジュアルはCSS、比較グラフはSVG、共有画像はCanvasで描き、外部画像APIやCDNには依存しません。日本語フォントもビルドに含まれます。

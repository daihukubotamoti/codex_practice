# こもれび鍛錬記 🌱

森の相棒「モク」と続ける、iPad / iPhone 向けの筋トレ記録PWA。React + TypeScript + Vite、IndexedDBによる端末内保存。ログイン・外部API・サーバー側DBは不要です。

## 起動する

Node.js 22.12以上（Node 24推奨）を用意し、このフォルダで実行します。

```sh
npm ci
npm run dev
```

ターミナルに表示されるアドレスをPCのブラウザで開きます。開発サーバーはPWAのオフライン動作確認用ではありません。

```sh
npm run build
npm run preview
```

本番ビルドは `dist/` に出力されます。本番プレビューは既定でポート4173です。サーバーを終了するには Ctrl+C。

## iPadで利用する

1. `npm run build` で生成した `dist/` を、HTTPSが使える静的ホスティング（Netlify / Cloudflare Pages / Vercelなど）に公開します。ビルドコマンドは `npm run build`、公開フォルダは `dist`。相対パスに対応しているため、GitHub Pagesの `/codex_practice/` 以下にも配置できます。公開サービスのアカウントや公開操作は別途必要です。
2. 公開されたHTTPSのURLを、iPadのSafariで開きます。
3. 初回はオンラインで読み込みを完了させます。
4. Safariの共有ボタン →「ホーム画面に追加」→「追加」。追加されたアイコンから起動します。
5. 以降はオフラインでも、読み込んだアプリと端末内の記録を使えます。OSによるサイトデータ削除や容量不足などでは保存領域が消える場合があります。

開発中に同じWi-FiのiPadで確認する場合は、PCのLANアドレスとViteのポートに接続できます（ファイアウォール設定による）。ただし、通常のHTTPのLANアドレスではService Worker/PWAのオフライン機能は使えません。PWA確認にはHTTPSの公開先を使ってください。

**このリポジトリには公開先のURLはまだありません。** GitHubへの反映やホスティングへの公開は自動では行いません。iPad Safari実機での最終確認は、HTTPS公開後に行ってください。

## 使い方

- **森のホーム**：モクをタップして会話。歩く・寝る・食べる・喜ぶ動きに変化します。成長状況・今週の履歴・週間ミッションを表示。
- **鍛錬を記録**：種目名を自由入力。重量（自重は0kg）・回数をセットごとに入力し、必要なセットを追加して保存。保存済み種目は候補ボタンから選べます。
- **鍛錬のあしあと**：月間カレンダーで日付を選択。過去の日付への記録追加、記録の編集・削除ができます。
- **成長と実績**：1セット10XP、種目ごとの自己ベスト更新で20XP。100XPごとにレベルアップ。レベル4/8/15でランクアップ。週間ミッションと実績バッジも表示します（ミッション自体の追加XPはありません）。
- **休息日**：ホームで今日を休息日として記録。鍛錬済みの日は休息日として重複登録しません。休息・時間の経過ではXPもランクも下がりません。
- **設定**：呼び名の変更、種目の名前変更・削除、JSONバックアップ・復元。種目削除時は関連する記録も確認のうえ削除されます。

### 自己ベストと成長

自己ベストは1セットの `重量 × 回数` の最大値です。同じ種目の以前に保存した記録を超えると報酬。重量のある最初の記録も対象です。0kgの自重トレーニングは通常XPのみ獲得します。XPは保存記録から再計算するため、編集・削除に伴い変わります。週間ミッションは端末のローカル日付・月曜日開始で集計し、追加XPを重複付与する方式ではありません。

### 保存とバックアップ

IndexedDBの `komorebi-training` データベース内に、種目・記録・休息日・設定をひとつの状態として保存します。成長と実績は保存データから再計算します。画面の保存成功メッセージはIndexedDBへの保存完了後に表示します。

データは**この端末、このブラウザ、この公開先のURL**に紐づきます。iPadとiPhoneで自動同期はしません。Safariのタブとホーム画面アプリは保存領域が異なる場合があるので、使用場所を決めてください。移行前に「設定・バックアップ」からJSONを書き出し、「ファイル」など安全な場所に保存。移行先でJSONを復元します。復元は現在の全データを置き換えるため確認が表示されます。不正な形式や10MBを超えるファイルは受け付けません。

プライベートブラウズは永続保存に向かないので通常モードを使ってください。SafariのWebサイトデータを消すと記録も消えます。定期的なバックアップを推奨します。JSONには記録がそのまま入るため、他人に公開しないでください。

同一の保存領域を複数タブで同時編集する使い方には対応していません。ひとつのタブ／ホーム画面アプリで記録してください。端末を使える人はアプリの記録も閲覧できます。認証によるアクセス制限はありません。

## 検証

```sh
npm test            # XP、PB、休息、バックアップ検証、週の境界
npm run build      # TypeScript型検査と本番PWAビルド
npm run test:e2e    # Chromiumで記録・再読み込み・編集・バックアップ復元・オフライン確認
```

E2Eはこのクラウド環境の `/usr/bin/chromium` を使う設定です。別のPCでは `playwright.config.ts` の `executablePath` を環境のChrome/Chromiumに合わせるか、削除して `npx playwright install chromium` を実行してください。

モク・背景はアプリ内のSVGイラスト、アイコンはLucide、フォントはNoto。フォントもビルドに含まれ、外部サービスへの接続なしで表示できます。動きを減らすOS設定にも対応しています。

## GitHub Pagesで公開する

`.github/workflows/deploy.yml` に公開用ワークフローを用意しています。GitHubのこのリポジトリの Settings → Pages → Build and deployment → Source を **GitHub Actions** に設定し、mainへのプッシュまたはActionsの「Deploy to GitHub Pages」を実行します。完了後のURLはActionsのdeployment出力で確認してください。公開先候補は `https://daihukubotamoti.github.io/codex_practice/` ですが、デプロイ成功までは利用できるとは限りません。コード公開の可否とGitHubプランによるPages利用条件はリポジトリの設定によります。
